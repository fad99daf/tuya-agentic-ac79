# 烧录与三元组授权区指南

> 面向:给 AC791N 故事机烧固件、写/换涂鸦授权码(三元组)的开发者与产线工装开发。
> 状态:2026-09-28 全链板上验证收官(发现→首烧→load→回落→配网→K6→自写号→断电/跨K6保留→区码激活)。
> 代码载体:`apps/common/LLM/tuya_agentic/tuya_auth_region.c/.h`(模块),`tuya_agentic_demo.c`(消费/注入点)。

## 0. 三十秒版本

| 你想做什么 | 怎么做 |
|---|---|
| **日常重烧固件** | 直接普通烧录。授权区、配网数据(VM)全保留,烧完开机直连,什么都不用重配 |
| **全新板首烧带码** | `app_config.h` 开 `TUYA_AUTH_EMBED_TEST_BIN`,96B bin 放 `cpu/wl82/tools/tuya_auth/auth_test.bin`,正常烧;烧完把宏注释回去 |
| **换授权码** | 烧写器**全片擦除** → (可选)带码烧 → 长按 K6 清配网 → 重新配网激活。**不擦区新码进不去,不清 VM 新码不生效** |
| **`TUYA_AUTH_RW_TEST`** | **恒为 0**。1/2 是 2026-09-28 的一次性板上验证钩子,已收官,留着会出产线事故(见 §7) |

## 1. 身份三层——为什么重烧固件不丢身份

| 层 | 位置 | 内容 | 谁写 | 何时读 |
|---|---|---|---|---|
| **固件** | flash 代码区 | 程序本身 | 烧录器 | — |
| **授权区(USER)** | flash `0x5FE000`,4K | 96B 三元组:product_key / uuid / auth_key | 产线烧写(或运行时写,见 §4C) | **仅激活那一刻** |
| **VM** | flash `0x5F4000`,0x8000 | devid / localkey / ssid / schema / region | 激活成功后固件写 | 每次开机(有 devid 即直连) |

两条实测铁律:

- **普通烧录不碰授权区**:分区表只给区占位;烧写器对**非空区不叠写**(双保险)。已写号区跨多次重烧、跨断电、跨 K6 均保留(板上验证)。
- **K6 只清 VM 里的涂鸦记录,不碰授权区**:长按 K6 = 云端解绑通知 + 清 VM + 重启进配网;授权区原样(板上以已写号区验证)。

## 2. 授权区在哪、地址契约

分区定义在 `cpu/wl82/tools/isd_config_rule.c`(及 loader 版 `isd_config_rule_loader.c`,**两处必须同值**):

```
[RESERVED_EXPAND_CONFIG]
USER_ADR=0x5FE000;    ← 钉死,紧贴 AUPACKRES(0x5FF000)前一扇区
USER_LEN=0x1000;
```

`0x5FE000` 是**三方契约**:烧写器镜像分区表按它生成;产线脚本按它直烧;固件运行期 `fopen("mnt/sdfile/EXT_RESERVED/user")` **按名**取址(不依赖此值,但地址对不上会打印 mismatch 自检失败)。

⚠ **千万别改回 `USER_ADR=AUTO`**——AUTO 随 app 大小/资源布局漂移,是 2026-09-17 首版方案写入 bug 的根源。改地址必须同步:isd_config_rule.c + isd_config_rule_loader.c + 产线脚本。

## 3. 96B 授权码:布局与生成

结构裸放区偏移 `+0`,**无任何文件头**(AUPACKRES 的 0x20 头是 packres 私有格式,与本区无关);多字节整数小端:

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 8 | magic `"TUYAAUTH"` |
| 8 | 2 | version u16 = 1 |
| 10 | 2 | head_size u16 = 96 |
| 12 | 17 | product_key(NUL 结尾,≤16 字符) |
| 29 | 21 | uuid(NUL 结尾,≤20 字符) |
| 50 | 33 | auth_key(NUL 结尾,≤32 字符) |
| 83 | 11 | reserved,全 0 |
| 94 | 2 | crc16 u16,CRC16-CCITT-FALSE(poly 0x1021, init 0xFFFF,无反射;校验向量 `crc16("123456789")=0x29B1`)覆盖字节 [0..93] |

生成工具(与固件 `tuya_auth_region_t` 逐字节一致,实测 crc/头 16 字节与板上 write/load 完全吻合):

```
python tools/gen_auth_bin.py <product_key> <uuid> <auth_key> cpu/wl82/tools/tuya_auth/auth_test.bin
```

⚠ **生成的 bin 是真实授权凭据**:不进 git(overlay `.gitignore` 已挡 `*.bin`)、不上传、日志/截图不得带出 auth_key。

## 4. 三种烧录形态

### A. 普通烧录(日常默认)

`TUYA_AUTH_EMBED_TEST_BIN` 保持**注释**(默认)→ 镜像不含 USER_FILE → 分区表仅占位。结果:授权区与 VM 全保留,开机 `already provisioned` 直连。**随便烧,无风险。**

### B. 首烧带码(全新板 / 授权区空白)

1. 生成 bin 放 `cpu/wl82/tools/tuya_auth/auth_test.bin`;
2. `app_config.h` 打开 `#define TUYA_AUTH_EMBED_TEST_BIN`;
3. 编译、正常烧录——isd_download 把 96B 随镜像烧进空区;
4. **烧完把宏注释回去**:不是为了防叠写(非空区本来不写),是防测试码继续混进后续镜像。

对已写号板开着此宏烧录也无害(不叠写),但请养成随手注释的习惯。

### C. 改码 / 换号(授权区已有码)

烧写器对非空区**不叠写**,所以换号必须先清区:

1. 烧写器**全片擦除**(顺带清掉 VM → 反正也要重新配网);
2. 按 B 带新码烧(或按 A 烧出空区,开机回落内置宏);
3. 长按 K6(或 App 移除设备)清 VM → 重新配网 → 激活消费新码(见 §5)。

> 运行时串口通道(代码就绪、transport 未接线,挂起):`auth write <pk> <uuid> <authkey>` / `auth show` / `auth erase` 一行搞定,免重烧。产线工装定版后接 `tuya_auth_region_serial_line()` 即活。

## 5. 换号必读:三元组只在激活时消费

**VM 里已有 devid 时,开机直接 `already provisioned` 直连,授权区里新写的码躺着不生效。** 完整换号流程必须含清 VM:

```
写新码 → K6/App移除(清VM) → 重新配网 → 激活(这一刻读区码)
```

- 同一 uuid 重复激活:云端**每次发新 devid**(实测到第 4 个);
- 换不同 uuid:云端是全新设备,旧设备记得在 App 里移除。

## 6. 开机日志速查

| 日志行 | 含义 |
|---|---|
| `[TUYA_AUTH] zone sclust=... flash=0x5FE000 len=0x1000 head16: 54 55 59 41 ...` | 区探测 + 前 16 字节裸照(magic/ver/size/pk 前缀肉眼可辨) |
| `[TUYA_AUTH] load OK: pk=... uuid=... key_len=32 crc=0x____` | 区校验全过(magic/版本/尺寸/字段/CRC),crc 与生成工具一致 |
| `[TUYA_AUTH] load: zone empty (erased)` | 区空白 → 回落内置宏(正常,首烧未带码时) |
| `[TUYA_AUTH] load: bad magic (...)` | 区内容既非授权码也非擦净态 → 脏数据,查写号流程 |
| `[TUYA_AUTH] load: CRC mismatch calc=... stored=...` | 内容损坏或布局不符,用 §3 工具重生成 |
| `[TUYA] triplet source: USER region @0x5FE000` | 三元组取自授权区(量产形态) |
| `[TUYA] triplet source: built-in macros (region empty/invalid)` | 回落 `tuya_agentic_demo.c` 顶部三宏(联调形态) |

## 7. `TUYA_AUTH_RW_TEST` 红线:恒为 0

2026-09-28 一次性板上验证钩子,**两档均已收官**,语义与事故场景:

| 值 | 语义 | 留着的后果 |
|---|---|---|
| 0 | 关(生产) | — |
| 1 | load 成功后**擦区** | **每块新写号板开机即被擦**,写号白做 |
| 2 | 区无效时用内置宏**自写号** | 空板永远自愈成固件里的宏码,`STRICT` 量产语义失效 |

收官证据存档:crc `0x9be4` 写/冷读三开机一致;断电重上(reset=LOW POWER)直接 load OK;K6 后无 write 再现 = 已写号区保留;区码驱动重配网激活第 4 个 devid 成功。

## 8. 宏回落与 STRICT

- `tuya_agentic_demo.c` 顶部 `TUYA_PRODUCT_KEY / TUYA_UUID / TUYA_AUTH_KEY` 是**兜底**:区无效时回落(日志明示来源)。联调期方便,量产固件建议填占位值,倒逼区码生效。
- `TUYA_AUTH_REGION_STRICT=1`(`tuya_auth_region.h`,默认 0):只认授权区、不回落宏——量产语义。**仅编译验证,板上未验**,启用前先走一遍 §4C 流程实测。

## 9. 挂起项(勿当已验)

| 项 | 状态 |
|---|---|
| 运行时串口通道 | 解析器就绪(`tuya_auth_region_serial_line`),UART transport 未接线 |
| `STRICT=1` 运行时 | 仅编译验证 |
| 已写号区跨 OTA 保留 | 未验(普通烧录保留已验) |
| 产线烧录通道(批量写号脚本/工装) | 用户挂起;杰里原生 AUTH_CODE=CSV 通道亦挂起 |

## 10. 坑清单(都踩过,别再来)

1. **`USER_ADR=AUTO`** → 地址漂移,写号写进错误扇区(2026-09-17 bug 根源)。
2. **对已编程扇区不擦直接叠写** → 位写坏。`tuya_auth_region_write()` 内部已按"先擦 4K 再写 96B 再回读"实现,产线脚本必须同样先擦。
3. **sclust 是 CPU 映射地址**不是 flash 原始地址:喂 `sdfile_reserve_zone_*` 原样直传,比对/打印先过 `sdfile_cpu_addr2flash_addr()`。详见 `tuya_auth_region.c` 头注释。
4. **真实授权码 bin 进 git/日志/截图** → 泄露即设备身份被盗用,只许存在于烧写工装与授权区。
5. **改码不清 VM** → 新码永远不被消费(见 §5)。
